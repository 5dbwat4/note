## How Is the GPU Different from a CPU? / GPU 与 CPU 有何不同？

So how is the GPU different from a CPU? Those that have interacted with the GPU already know this. We'll move on to more advanced things in a minute. But for the rest of you, I think it's very important to understand the model, the philosophy in some sense, of how they're different. So a CPU is designed for quick, serial execution where you have complex branching logic, complex conditionals, complex control flows. Because of this, a CPU, generally speaking, has really big control units. And it has a few ALUs that can do mathematical or other operations. But this is meant to run very quickly. So you want to go as fast as possible and have low latency. The time between when you get an instruction and when you complete it should be very, very short. That's the general CPU design philosophy. In contrast, the GPU is really about throughput. And the plot on the right, I think, is a great pictorial illustration of, when you change these philosophies, what you end up getting. So in a GPU, maybe you dispatch a task, it takes a long time for it to finish. It might be that you process a task, and then you stop, and then you go work on another task, and then you go back and work on another task. But in general, even though your tasks don't finish quickly, you're getting large aggregate throughput across all of your tasks. And what enables this is having tons and tons of lightweight cores. So a GPU has hundreds and hundreds of compute units that are packed into a chip. And all of these can execute in parallel. So this is a very different mode of programming and thinking compared to a CPU.

GPU 与 CPU 有何不同？那些已经接触过 GPU 的人已经知道了这一点，我们马上会进入更高级的内容。但对于其他人，我认为非常重要的是理解它们不同的模型——在某种意义上，是理念上的不同。CPU 是为快速的串行执行(serial execution)而设计的，涉及复杂的分支逻辑(branching logic)、复杂的条件判断(conditionals)、复杂的控制流(control flows)。因此，CPU 通常有非常大的控制单元(control units)，以及少量的算术逻辑单元(ALU)来进行数学或其他运算。但这是为了非常快速地运行——你希望尽可能快地执行并具有低延迟(latency)。从收到指令到完成指令的时间应该非常非常短。这是 CPU 的一般设计理念。相比之下，GPU 真正关注的是吞吐量(throughput)。右边的图，我认为是对当你改变这些理念时最终会得到什么的一个很好的图示说明。在 GPU 中，也许你分派一个任务，它需要很长时间才能完成。可能是你处理一个任务，然后停下来，去处理另一个任务，然后再回来处理另一个任务。但总的来说，即使你的任务不会很快完成，你在所有任务上获得了巨大的总聚合吞吐量(aggregate throughput)。实现这一点的方法是拥有大量轻量级核心(lightweight cores)。GPU 有数百个计算单元(compute units)封装在一个芯片上，所有这些都可以并行执行。所以这是一种与 CPU 截然不同的编程和思维模式。

## The Software and Programming Model of a GPU / GPU 的软件与编程模型

Now, we have the hardware mental model in place. And now we're going to start talking about the software and programming model of a GPU. So there's three different important players that live in the execution model of a GPU. So there's a thread. And if you're familiar with multiparallel programming of any kind, you know what a thread is. A thread is a lightweight thing that's running in parallel and doing some work. In a GPU, an important thing about the threads is they follow the SIMT model, which means that all of the threads that you have are executing the same exact instructions. They're going to have different inputs, which means that the threads can actually do separate useful work, but the instructions they execute have to all be the same. And this has important implications for both the efficiency of your code as well as the programming model. If the threads can do all sorts of different stuff, it becomes very hard to program. GPUs are this tradeoff between programmability and efficiency. Now, a block is a group of threads. And the reason why a block is a relevant object is that a block is guaranteed to run on a single SM. ### Trick 1: Control Divergence / 技巧一：控制分歧

The first one is a GPU-specific thing. And it relates to one of the things I said before, the SIMT model. So in a GPU, every thread is executing the same thing. Now, what happens if you write an If statement on a piece of code that executes on a GPU? On a CPU, it's quite clear what happens. On a CPU, you will either pick one branch or the other, you will execute that branch. And you will move on with your life. In a GPU, you will do something actually quite different and slightly counterintuitive. Every thread has to execute the same instruction. So actually, every thread will execute both If and the Else. But if you're not part of If branch, you will just mask out that computation. You'll just sit idle. And so whenever you have a conditional, your mental model for the execution kind of looks like this. Part of your threads will diverge based on this If statement. Some of them will go to the bottom branch, some of them will go to the top branch. And the bottom branch ones will execute first, top branch ones will wait. And then the top branch ones will execute, and the bottom branch ones will wait. So in order to execute an If statement, you're actually walking through both of these. And then some of the threads are just waiting, doing nothing if they're on the wrong side of the branch. And this is called control divergence. And this is nice in some ways because it simplifies programming. It's not nice in that you now have these big compute gaps where your GPU is doing nothing. This is one of the reasons why you really do not want to write If statements. If you look at GPU code, if you have a ReLU, you'll often find you're multiplying with zeros or multiplying with masks instead of doing an If statement where you're updating half because a multiplication is going to all go at once. And an If statement might actually have to wait two clock cycles or something like this, two operations. So that's the first thing. But, that's a separate story from all this memory stuff, which is the main narrative or the main story of this.

第一个是 GPU 特有的，与我之前提到的单指令多线程(SIMT)模型有关。在 GPU 中，每个线程都执行相同的指令。那么，如果你在 GPU 上执行的代码中写了一个 If 语句会发生什么？在 CPU 上，情况很清楚：你要么走一个分支，要么走另一个分支，执行那个分支，然后继续。在 GPU 上，你会做一些非常不同且有点反直觉的事。每个线程必须执行相同的指令，所以实际上每个线程会同时执行 If 和 Else。但如果你不属于 If 分支，你只会屏蔽(mask)掉那个计算——你只是空闲。所以每当你有一个条件分支时，执行的思维模型看起来是这样的：一部分线程会根据这个 If 语句发散(diverge)，一些去下面的分支，一些去上面的分支。下面的分支先执行，上面的分支等待；然后上面的分支执行，下面的分支等待。所以为了执行一个 If 语句，你实际上遍历了两者，然后部分线程只是在等待——如果它们不在正确的分支上，就什么都不做。这被称为控制分歧(control divergence)。这在某些方面很好，因为它简化了编程。不好之处在于你有了这些大的计算间隙，GPU 什么都不做。这就是为什么你真的不想写 If 语句的原因之一。如果你看 GPU 代码，如果你有一个 ReLU，你经常会发现你是在乘以零或乘以掩码(mask)，而不是做一个 If 语句来更新一半——因为乘法是一次性完成的，而 If 语句可能需要等待两个时钟周期或类似的两次操作。这是第一件事。不过，这与内存相关的主要叙事是分开的。
