OK, so let's start back and rewind the clock back to '21. So the CLIP model, which some of you might be familiar with, is a lot of the foundation of modern VLMs. And so we can go through this a bit in more detail. So CLIP stands for Contrastive Language Image Pre-Training. And a bit of historical context is around that time GPT-3 had already happened. GPT-2. All the language models had already gone into this foundation model era. Neovision was still-- there were some efforts, but traditionally had been based on large annotated data sets, such as ImageNet, and training models, such as the ResNet, on these data sets and doing a bunch of other things, like data augmentation, and getting really good performance. And so the researchers at OpenAI were wondering, is it possible to leverage the large amount of image and textual captions out there? So inspired by this idea in language where you could just scrape the internet, you have all this text, it's very noisy. But somehow if you train a large enough model, you can make sense out of this and generate something useful. So what was the equivalent of that for images? As a result, CLIP was born. And the idea of CLIP is fairly simple and straightforward. So the idea here is that suppose I give you a bunch of image-text pairs. So let's say I give you 32,000 of these. OK, so what I'm going to do is for each image I'm going to encode it using an image encoder, which I'll explain later, into a vector. So I'm going to have 32,000 of these image encodings. I'm going to also do the same thing with the corresponding text. So that will give me T1 through TN. So these are the embeddings of the text. These are embedding of the images. Now, the objective I want to set up is that I want the image-- let's take I1. So I1 is aligned with T1. So I want this alignment, the dot product between these two embeddings to be much larger than the dot product between I1 and all the other texts, OK. And conversely, I also want for this text to say that this dot product is larger than the dot product between T1 and all the other images. So that, in a nutshell, is the CLIP objective. And you can imagine doing-- there's basically 2 times N different softmax classification problems. So here's the code. So you get a n by d matrix for the image encodings and n by d times for the textual embeddings. You normalize and you take this dot stop product with some temperature. And then you compute the cross entropy, OK. So it's basically a multi-class classification problem, where the examples are structured in this m by n matrix form. OK, any questions about that?

好，让我们回到 2021 年。CLIP 模型——你们中有些人可能熟悉——是现代视觉语言模型(VLM)的基础。我们来更详细地过一遍。CLIP 代表对比语言-图像预训练(Contrastive Language-Image Pre-Training)。一些历史背景是：那时 GPT-3 已经出现了，GPT-2 也是。所有的语言模型已经进入了基础模型(foundation model)时代。视觉方面——虽然有一些努力——但传统上一直基于大型标注数据集(如 ImageNet)，并在这些数据集上训练模型(如 ResNet)，配合数据增强(data augmentation)等其他技术，获得了非常好的性能。所以 OpenAI 的研究人员在想，是否有可能利用那些大量的图像和文本描述？受到语言领域想法的启发——你只需从互联网上抓取，有所有这些文本，尽管非常嘈杂，但如果你训练一个足够大的模型，你就可以从中理出意义并生成有用的东西——那么对于图像来说，等价物是什么？结果，CLIP 诞生了。CLIP 的想法相当简单直接。假设我给你一堆图文对(image-text pairs)。比方说，我给你 32,000 个这样的对。好，对于每个图像，我将使用一个图像编码器(image encoder)——我稍后会解释——将其编码成一个向量。这样我就有 32,000 个图像编码向量。我对相应的文本也做同样的事情，得到 T1 到 TN。这些是文本的嵌入(embedding)，那些是图像的嵌入。现在，我想设定的目标是：对于 I1——它应该与 T1 对齐——我希望这两个嵌入之间的点积(dot product)远大于 I1 与所有其他文本之间的点积。反过来，我也希望对于这个文本，这个点积大于 T1 与所有其他图像之间的点积。简而言之，这就是 CLIP 的目标。你可以想象，这基本上是 2 乘以 N 个不同的 softmax 分类问题。这是代码。你得到一个 n×d 的图像编码矩阵和一个 n×d 的文本嵌入矩阵。你做归一化，然后用某个温度参数(temperature)计算点积，然后计算交叉熵(cross entropy)。所以这基本上是一个多类分类问题(multi-class classification problem)，其中样本以这种 m×n 矩阵形式组织。好，有问题吗？
